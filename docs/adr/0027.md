# ADR-0027：Credential Manager 声明式登录握手（RSA / JWT）

- 状态：Accepted
- 日期：2026-10-22
- 关联：docs/architecture.md §9.2

## 背景

企业后台常见「取公钥 → RSA/SM2 加密口令 → 换 JWT」的登录，与声明式 Connector 的明文 `login` 模式不兼容。备选：

1. 每系统写代码 Connector（成本高）
2. 人工灌 Bearer 到 OpenBao（无法续期）
3. 工作流里先 login（违背 Credential Manager 缓存/single-flight）
4. 任意 pre-request 脚本（多租户不可接受）

## 决策

扩展 `CredentialManager` 的 `mode=login`，增加**白名单声明式握手**，认证仍挂在连接/`connector_instance.config.auth`，不进 Tool Spec：

1. `prepare[]`：最多 5 步 GET/POST，JSONPath `capture` 到上下文
2. `transform[]`：白名单算子（首期 `rsa_encrypt_json` / `rsa_encrypt` / `base64` / `json_stringify`）
3. `body`：模板仅允许 `{{secret.*}}` / `{{capture.*}}` / `{{vars.*}}` / `{{uuid}}` / `{{now_ms}}` / `{{random_hex:N}}`
4. `ttl_from: jwt_exp`：按 JWT `exp` 续期（可配 `ttl_skew_s`）；失败回退 `ttl_s`
5. 既有 Token 缓存、single-flight、401 刷新一次、凭据不进日志/模型上下文不变

请求级 HMAC 签名仍按架构表走代码 Connector 插件；本 ADR 只覆盖**换票握手**。

## 影响

- `src/aip/connectors/credentials.py` 与测例 `tests/test_credential_login_handshake.py`
- 架构 9.2「用户名密码换 Token」补充「可声明 prepare/transform」
- 后续可加 `sm2_encrypt`、Cookie 会话；不得引入任意用户脚本
- 修改本决策须新建 ADR 并将本 ADR 标为 Superseded
