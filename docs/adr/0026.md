# ADR-0026：sql_readonly 连接挂载 system_connection（scheme 扩展）

- 状态：Accepted
- 日期：2026-10-22
- 关联：docs/architecture.md §9.1、§9.5、§9.6；计划 `docs/superpowers/plans/2026-10-22-swagger-and-sql-readonly.md`

## 背景

架构 9.5 要求数据库只读连接器（参数化 SQL 模板、只读账号、超时与 LIMIT）。现有 `system_connection.scheme` 仅 `http`/`https`，`base_url` 亦按 HTTP(S) 校验，无法表达 PostgreSQL / MySQL 下游。

备选：DSN 全放 `connector_instance.config`（方案 B）会使公司/环境/TLS 例外审批与 HTTP 连接分叉，控制台与审计不一致。

## 决策

采用**方案 A**：扩展 `system_connection.scheme`，首期增加 `postgres`、`mysql`。

1. `base_url` 为**不含密码**的 URI，例如 `postgres://db-host:5432/erp_ro`、`mysql://db-host:3306/erp_ro`。
2. 用户名/密码仅存 OpenBao，经 `credential_ref` 引用。
3. `tls_mode`：`system_ca` | `custom_ca` | `insecure`（**首期不对 DB 使用 `pinned`**）；`insecure` 与明文库连接仍走传输例外审批与到期日（对齐 9.6）。
4. `connector_instance.kind` 增加 `sql_readonly`；查询模板表挂在实例上，Runtime 按 `operation`=`template_key` 执行。
5. **禁止**经本通道写库；模板仅允许单条只读语句。

## 影响

- 更新 `docs/specs/system-connection.schema.json` 与 DB CHECK；HTTP 连接行为不变。
- 修改本决策须新建 ADR 并将本 ADR 标为 Superseded。
- SQL Server / MongoDB 另开切片，可再扩展 scheme 或独立模板模型。
