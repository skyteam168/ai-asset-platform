# ADR-0003：工作流引擎：自研 step journal（spike 后选定，DBOS Transact 未采用），保留 WorkflowExecutor 抽象

- 状态：Accepted
- 日期：2026-10-20
- 关联：docs/architecture.md 第 8.5、16.1 节；spike 记录 docs/ops/spike-adr-0003-workflow-engine.md

## 背景

自研 step journal 与 DBOS Transact 在 M5 前做 spike 后二选一（8.5）。两个原型实现同一 WorkflowExecutor 抽象，用同一组故障场景（kill -9、Worker 不再回来、Saga、人工任务超时跨崩溃、持久化 wait、跨版本发布、吞吐）对比，18 个用例全部通过。

## 决策

采用自研 step journal：wf_run / wf_step / wf_task 存 PostgreSQL，Worker 用 FOR UPDATE SKIP LOCKED 认领并持有租约，租约过期任何 Worker 可接手；定时器用 wake_at 扫描；Run 钉住 DSL 与 Release 快照。保留 WorkflowExecutor 抽象，日后可替换。

不采用 DBOS Transact 的原因：开源版不能自动接管消失的 Worker（死亡 executor 判定属于商业版 Conductor）；恢复只认同一 application_version，与“Run 钉住 Release、引擎升级不影响在途 Run”冲突；系统表在独立 schema，无法纳入 RLS 与审计；DSL 解释执行用不上它最主要的价值；依赖面大且 3.x 仍有破坏性变化。

## 影响

- 引擎正确性由平台负责：spike 的故障场景扩展为 M5 常驻回归（另加循环、并行、取消、长步骤续期）。
- 生产节点需要 NTP 并告警时钟跳变（持久化定时器依赖墙上时钟）。
- 修改本决策必须新建 ADR 并将本 ADR 标记为 Superseded。
